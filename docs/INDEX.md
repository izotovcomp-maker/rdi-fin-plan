# Карта docs/

Что где лежит и **когда открывать**. Не читай всё подряд — выбери по стадии работы.
Правила для агента короткие в [../AGENTS.md](../AGENTS.md), подробности — в `agent/`.

Общая база знаний по Б24 лежит **вне проекта**, в `/projects/docs/`:
`rules-b24/INDEX.md` (грабли и правила) и `b24-rest-docs/` (клон офиц. документации).

## Память проекта (журнал)

Пять файлов, точка входа для нового исполнителя — `handoff.md`.

| Файл | Роль | Как меняется | Когда читать |
|------|------|--------------|--------------|
| [handoff.md](handoff.md) | С чего начать новому исполнителю | при передаче | передача проекта |
| [project-brief.md](project-brief.md) | Что за проект и зачем; скоупы, плейсменты, прод URL | редко | первый рабочий запрос |
| [state.md](state.md) | Где мы **сейчас** + следующие шаги | постоянно (перезапись) | первый рабочий запрос |
| [changelog.md](changelog.md) | Что уже **сделано**, по датам | дописывается, новое **сверху** (под маркером в файле) | нужна история |
| [decisions.md](decisions.md) | **Почему** так, а не иначе (D-NNN) | дописывается, новое **снизу** (под маркером в файле) | перед неочевидным выбором |

`changelog.md` и `decisions.md` никогда не переписываются и не удаляются — только
добавляются новые записи (append-only). Направление вставки у них разное и осознанно:
`changelog.md` читают как «что нового» без скролла до конца — новое сверху; `decisions.md`
читают как хронологию причин, где решения ссылаются друг на друга по порядку
(«отменяет D-NNN») — новое снизу. Куда именно вставлять — смотри маркер
`<!-- Новые ... добавляй ... -->` в начале каждого файла, не полагайся только на эту таблицу.

## Правило для этой папки

Новый файл в `docs/` → добавь строку в эту таблицу и поле `description:` в начало файла
(одна строка: о чём файл и когда его открывать).
