# Документация: где что искать (порядок обязателен)

Вынесено из AGENTS.md. Краткое жёсткое правило остаётся в AGENTS.md, здесь — полная версия.

**Общая папка знаний — `/projects/docs/`** (одна на все проекты, копий в проектах не держим):
`rules-b24/` — грабли и правила Б24 (`INDEX.md` + файлы), `b24-rest-docs/` — клон официальной
документации. Правило или грабля обновляется **только там** — сразу для всех проектов.
Нет папок на этой машине — создай их и склонируй документацию (см. пункт 2 цепочки).

## Что искать где

| Вопрос | Где смотреть | Чем |
|--------|--------------|-----|
| Как устроен код шаблона (`b24()`, `storeRead`, `accessAllows`, `bind.php`) | сам код в `www/` | `grep` / чтение, **не MCP и не документация Б24** |
| Что за проект, что сделано, почему так решили | файлы проекта — карта в [../INDEX.md](../INDEX.md) | чтение файла |
| Грабля, ошибка, «не работает», нюанс Б24 | `/projects/docs/rules-b24/` | цепочка ниже, шаги 1→4 |
| Параметры метода REST, формат ответа, события, права | клон `/projects/docs/b24-rest-docs`, затем MCP | цепочка ниже, шаги 2→3 |

## Цепочка поиска по Б24 — строго по порядку

**Не перескакивай шаги.** Идти в следующий можно, только если предыдущий **реально
выполнен** и не дал ответа. Применяется к любому вопросу про Б24 (метод, событие, права,
OAuth, install, плейсмент), а не только когда что-то сломалось. Не гадай.

1. **Правила** — сначала `grep` по [/projects/docs/rules-b24/INDEX.md](/projects/docs/rules-b24/INDEX.md)
   (несколько синонимов: `batch`, `scope`, `token`…). Нашёл подходящее — **прочитай файл правила целиком**
   и ответ строй от него. Этот шаг нельзя пропускать, даже если ответ «и так известен».
2. **Локальный клон офиц. репозитория** `bitrix-tools/b24-rest-docs`
   (Documentation as Code, ~3490 файлов) в `/projects/docs/b24-rest-docs`:
   ```bash
   grep -rn "<термин>" /projects/docs/b24-rest-docs --include="*.md"
   ```
   - Папки нет на машине → склонировать:
     `git clone --depth 1 https://github.com/bitrix-tools/b24-rest-docs.git /projects/docs/b24-rest-docs`
   - Подозрение, что данные устарели → `cd /projects/docs/b24-rest-docs && git pull`
3. **MCP `bitrix24-docs`** — только если шаги 1–2 не дали ответа или нужна проверка на свежесть.
   Инструменты: `bitrix-search` (поиск), `bitrix-method-details` (метод), `bitrix-event-details`
   (событие), `bitrix-app-development-doc-details`, `bitrix-article-details` (статья).
   - Ошибка валидации параметров (например, `doc_type` — это **список**: `["event"]`, не строка) —
     **исправь вызов и повтори**, не продолжай вслепую.
   - Пустая или нерелевантная выдача **не доказывает отсутствие** — переформулируй запрос (синонимы,
     русский/английский, имя метода/события) и проверь клон. Выводить «этого нет в Б24» можно только
     после ≥2 разных запросов без ошибок и поиска в клоне.
4. **Online-ссылки** — последний шаг, только если 1–3 не дали ответа:

| Что | Ссылка |
|-----|--------|
| Битрикс24 — OAuth и токены | https://apidocs.bitrix24.ru/settings/oauth/auto-renewal.html |
| Битрикс24 — виджеты CRM | https://apidocs.bitrix24.ru/api-reference/widgets/crm/index.html |
| Битрикс24 — справочник REST API | https://apidocs.bitrix24.ru/api-reference/ |

**Нашёл решение не через правила?** Если грабля вневременная (не специфична
для конкретного клиента/проекта) — оформи файл в `/projects/docs/rules-b24/` + строку в
`/projects/docs/rules-b24/INDEX.md` (не в папку проекта), чтобы не искать повторно в следующий раз.
