## Старт после онбординга

На команду «стартуем» / «деплой» / любой первый рабочий запрос — если онбординг уже
пройден, **сразу деплою `bash deploy.sh`** (env.php создастся сам) и прошу
зарегистрировать local-app в Б24 + вписать `B24_CLIENT_ID`/`SECRET` ([../how-to-link.md](../how-to-link.md)).
Вопросы задавай, только если без ответа нельзя продолжить и вывести его из проекта
(`docs/project-brief.md`, `source/`, кода) невозможно. Не спрашивай то, что уже известно.
Перед деплоем **в прод** — проход по [rule-b24-security-baseline](/projects/docs/rules-b24/rule-b24-security-baseline.md).

## Раскладка на сервере — ОДНА папка

Шаблон деплоится **одной папкой** в `<DEPLOY_ROOT>/<slug>/` (на наших серверах `/var/www/b24/<slug>/`;
slug = имя папки проекта). `data/` тоже здесь (store защищён `<?php exit;?>`-префиксом в .php-файлах,
веб не достаёт). `deploy.sh` в шаблоне правильный — не переделывать под другую раскладку.
Данные серверов (домен, пути, пользователь) в коде и в этих файлах не хранятся — только в профилях деплоя.

```
<DEPLOY_ROOT>/
  <slug>/          ← деплой одной папкой
    index.php
    env.php        ← не в git, создаётся deploy.sh при первом деплое
    api/
    css/
    js/
    template.html
    data/          ← файловый store, не в git
```

Код подхватывается сразу; блок веб-сервера для нового slug добавляется вручную.

## Caddy + PHP-FPM — следствия для шаблона

На наших серверах (`prod`, `lab`) — **Caddy + PHP-FPM**. Caddy проксирует каждый проект через `uri strip_prefix` и `php_fastcgi`. У заказчика веб-сервер может быть другим — см. [../deploy-targets.md](../deploy-targets.md). Что из этого вытекает и УЖЕ учтено в шаблоне:

- **`.htaccess` не используется by design.** Caddy его не читает. Защита state'а — через `<?php exit;?>`-префикс в `.php`-файлах.
- **Handler URL в карточке B24 local-app заканчивается на `/index.php`**, не на `/`.
- **`template.html`, не `index.html`** — `file_server` в Caddy по умолчанию отдаёт `index.html` как статику раньше PHP. `template.html` этого не триггерит.
- **Права `data/`** — PHP-FPM (`www-data`) пишет в `data/`, а файлы деплоятся другим пользователем. `deploy.sh` выставляет группу веб-сервера и права из профиля (`WEB_GROUP`, `DATA_MODE`: `2770` на `prod`, `0777` на учебном `lab`). Содержимое защищено `<?php exit;?>`, не правами ФС. Дополнительно на `prod` Caddy отдаёт 404 на `*/data/*`, `*.log`, `*.example`, `.git*`, `.env*` (блок `@blocked`).
- **`APP_URL` в `init.php` (1%-кейс, чужой хостинг) определяется неверно** при Caddy-подобном `uri strip_prefix`: `SCRIPT_NAME` приходит без префикса пути. `deploy.sh` пишет `APP_URL` напрямую из профиля, без автоопределения. Актуально только для [../how-to-link-ALL.md](../how-to-link-ALL.md).
- **REFERER-fence в session-gate двусторонний** — пропускает и B24-портал, и self-APP_URL. iframe-reload после `BX24.installFinish()` приходит с self-REFERER, без этого мигнёт 403 между установкой и финальной страницей.

### Блок Caddy для нового проекта

Вставляется вручную в блок домена на сервере (значения — из профиля; `deploy.sh`
печатает уже подставленный вариант):

```
handle /<slug>* {
    uri strip_prefix /<slug>
    root * <DEPLOY_ROOT>/<slug>
    php_fastcgi unix/<PHP_FPM_SOCK>
    file_server
}
```

Затем перезагрузка Caddy командой владельца сервера (`<CADDY_RELOAD_CMD>` из профиля).
Один раз на домен рекомендуется блок `@blocked` (закрывает `data/`, логи, `.git`, `.env`) —
`deploy.sh` напомнит, если его нет.

## Права приложения («Настройка прав»)

Каждый раз, когда просишь человека создать или изменить приложение в портале, **называй точный список прав** для поля «Настройка прав» в карточке (из «Скоупы Б24» в `docs/project-brief.md`: минимум `crm user placement`, + `department`, если доступ по отделам (режим по умолчанию, [rule-b24-department-based-access](/projects/docs/rules-b24/rule-b24-department-based-access.md)), + то, что требуют фичи). Появилась фича с новым правом — скажи, какое право добавить, и что токен надо обновить (см. [rule-b24-scope-add-needs-token-refresh](/projects/docs/rules-b24/rule-b24-scope-add-needs-token-refresh.md)). Не полагайся на то, что человек помнит список.
