## 2026-10-09 — Деплой правок (стадии/цвета, «По объекту» без периода) на prod

- Второй хотфикс: стадии смартов всё ещё показывались неверно (селектор — первая стадия воронки «Инициализация», вместо фактической). Теперь `id` = статусная часть `STATUS_ID` (сверено с докой b24-rest-docs, how-to-get-stages-with-semantics); юнит-тест мока переведён на реальный формат

- Дальше: человек снимает пробу `pay_by_deal_1046` через «Диагностику» и проверяет реестр/«По объекту» на живых данных
- Связанные решения: D-008, D-009

## 2026-10-09 — Правки по обратной связи: стадии/статусы и «По объекту» без периода
- Корневой баг найден: сбор stageId в `plan.php` читал только camelCase, портал в Y-режиме отдаёт капс (`STAGE_ID`) → список стадий приходил пустым, реестр и «По объекту» показывали сырые statusId без имён/цветов портала. - Фильтры по стандартным полям в Y-режиме не проверены (D-008) — выборка по объекту перепроверяется локально (`finItemsByParent`), в `plan-debug.php` добавлена проба `PARENT_ID_1038` для снятия сырого ответа после деплоя
- Проверено: `php -l` всех файлов, `node --check app.js`, 16 юнит-проверок хелперов на моке b24 — зелёные; на живом портале проверит человек (деплой не выполнялся)
- В план поставлено редактирование полей смартов из «По объекта» (плашка ✍ у изменённых строк, «Подтвердить и отправить все изменения» / «Отменить изменения») — см. state.md
- Связанные решения: D-008, D-009
